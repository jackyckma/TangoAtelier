# Tango Atelier — 生成引擎技術規格文件

## 主題：如何讓規則式生成引擎「聽起來像探戈」又「不會每次都一樣」

版本：v1.0　補充對象：《探戈鋼琴／吉他學習網站 — 專案文件》第 4、6、7 節（系統架構、資料模型、Phase 規劃）

---

## 1. 問題定義

生成引擎面對兩個互相拉扯的目標：

1. **風格保真度（Fidelity）**——生成結果要讓聽者辨認出「這是探戈／米隆加／華爾滋」，甚至進一步辨認出「這比較像 D'Arienzo 還是 Di Sarli」
2. **多樣性（Variety）**——同一個樂團風格、同一組參數，多次生成不能聽起來像同一首歌換了幾個音

單純調整「隨機性大小」這個旋鈕無法同時滿足兩者：隨機性太低 → 每次都很像同一首歌的翻版；隨機性太高 → 聽起來不再像探戈。解法是**分層**：把「不能變的骨架」和「可以自由變化的細節」拆開，只在被規則限制過的空間裡做隨機化。

---

## 2. 核心架構：七層分層生成流程

生成不是「一次到位」，而是像 Schenkerian 音樂分析描述調性音樂的方式——背景骨架先定，再逐層闡述成中景、前景。每一層決定下一層的邊界，隨機性只發生在被上層規則限制過的選擇空間內。

### 第一層：曲式骨架（Form Skeleton）

- 從該樂團 Style Profile 允許的曲式模板中選一個（intro–A–A'–B–A'–coda 等）
- 決定每段小節數（探戈曲式慣例以 8 或 16 小節為單位，此層**幾乎不隨機化**——段落長度亂了就不像探戈）
- 輸出：一份「段落時間軸」（段落名稱、起訖小節、預期情緒/張力等級）

### 第二層：和聲骨架（Harmonic Skeleton，樂句層級）

- 以「樂句」（通常 4 或 8 小節）為單位生成，不是逐一和弦生成
- 每個樂句**必須**以特定終止式收尾（如 V7♭9 → i），此為硬規則
- 樂句中段從 Style Profile 的 `harmonic_tendencies` 機率權重表抽選（是否插入次屬和弦、是否借用同主音調式和弦、是否走下行五度圈）
- 此層的機率權重表即為樂團風格差異的核心來源（例如 D'Arienzo 的借用和弦權重低、Pugliese 的權重高）

### 第三層：節奏骨架 + 微時間變化（Rhythmic Skeleton + Humanization）

- 套用該風格核心節奏型態（Marcato en cuatro/en dos、Síncopa、Habanera、3+3+2 等），型態本身**固定**
- 疊加微小的 timing/velocity 隨機抖動（人性化處理），避免機械複製感
- 此層的抖動幅度可設為使用者可調參數（對應原專案文件 Phase 5 的「參數微調」）

### 第四層：聲部進行與和弦排列（Voicing）

- 決定每個和弦的實際音高排列方式（八度低音疊加、密集排列、開放排列等）
- 硬規則：相鄰和弦之間盡量平滑聲部進行（parsimonious voice leading，各聲部移動距離最小化）
- 此層有自由變化空間：同一個 Am 和弦每次生成可以用不同排列，只要平滑進行規則不破

### 第五層：旋律生成（受約束的隨機漫步）

- 不是純隨機音高，而是「在和弦音附近做有方向性的隨機漫步」：
  - 強拍優先落在和弦音
  - 弱拍可走鄰音/經過音（呼應樂團的 chromaticism 傾向參數）
  - 樂句整體要符合「問句－答句」輪廓（問句收在屬和弦造成懸念、答句解決到主和弦）
- 裝飾音（倚音、碎音、半音經過句）依 Style Profile 的 `ornamentation_density` 參數機率插入

### 第六層：重複段落的「漸進闡述」變形（Elaboration Transform）

- 呼應探戈演奏心法的「從簡到繁」黃金法則：同一主題第二次出現時套用變形轉換
- 可用的變形手法（依機率或依段落位置決定套用哪個）：
  - 提高裝飾音密度
  - 左手從單純和弦改為 walking bass
  - 對特定和弦套用再和聲化（次屬和弦替換、三全音替代）
  - 提高力度對比與 rubato 幅度
- 此層專門負責讓 A 段與 A' 段「像同一個故事講兩次、但更豐富」，而非簡單複製貼上

### 第七層：配器分配（Instrumentation Assignment）

- 依使用者選擇的編制（鋼琴獨奏／+吉他／+班多鈕琴／完整 Orchestra），把前面各層產出的聲部分配給對應樂器
- 鋼琴獨奏：雙手扛所有聲部（左手節奏骨架＋右手旋律＋裝飾）
- 加吉他：吉他接手部分節奏骨架，鋼琴左手騰出空間做旋律性呼應句
- 加班多鈕琴：對位／裝飾旋律線分給班多鈕琴聲部

## 3. 延伸架構：意圖建模（Intention Modeling）

七層流程解決了「像不像探戈」，但仍是**由左到右、逐層往前生成**，沒有「知道自己要去哪裡」的全域規劃能力——這是人類作曲跟規則引擎最大的差異：作曲家的選擇是在服務一個尚未抵達的目標（「這個時刻贏得了什麼、又為接下來鋪墊了什麼」），會回頭修正；規則引擎的機率抽樣只往前看，不往回看。

若要讓生成結果**功能上**呈現這種「意圖感」（不涉及真正的主觀體驗，只談結構行為），建議在七層流程之上加一層「錨點式生成（Anchor-Based Generation）」：

### 3.1 結構錨點（Structural Anchors）

在跑第一層曲式骨架時，除了段落時間軸，額外標定幾個關鍵錨點：

- 全曲情感高潮落在哪一小節
- 主題再現（A'）落在哪一小節
- 主終止式落在哪一小節

這些錨點可先用一組模板定義（探戈曲式本身就有慣例：A 段結束在屬和弦懸念、A' 再現時情感達到高潮），不需要即時運算決定。

### 3.2 雙向填充（Bidirectional Infill）

第二至六層在錨點之間生成時，改為**雙向**推進，而非單純從頭到尾往前生成：

- 從段落起點往下一個錨點推進（forward pass）
- 從錨點往回推（backward pass），確保錨點本身能被自然抵達，而不是硬接上去
- 兩個方向在段落中點會合、做一致性檢查（和聲/旋律銜接是否平滑）

實作上可以先用簡化版本：錨點處的和聲/力度/節奏密度目標值先定好，中間段落的生成用線性或指數插值（interpolation）決定張力曲線的目標值，再由第二至六層的機率抽選在這個目標值附近選擇，而不追求真正的雙向搜尋演算法（那個複雜度較高，可留待後續迭代）。

### 3.3 全域張力曲線（Tension Curve）

定義一條數值曲線，描述不和諧度、力度、節奏密度隨小節數的目標走勢（對應演奏心法裡「動態對比」「彈性速度」的量化版本）。生成流程的每一層在做機率選擇時，除了原本的風格權重，額外加入「目前小節的張力目標值」作為修正因子——例如高潮小節附近，第二層和聲選擇會提高不和諧和弦（減七、借用和弦）的機率，第三層節奏選擇會提高切分密度。

### 3.4 動機的鋪墊與回收（Motif Setup & Payoff）

第五層生成旋律時，允許引擎標記某個短動機片段為「待回收」，並在第一層規劃階段就登記：這個動機必須在某個後續錨點（通常是 A' 再現或 coda）以變形手法重現。這對應第六層的「漸進闡述」機制，但差異在於：這裡的重現是**在生成早期就被排程好**的，不是逐段落即興決定，藉此製造「前面埋的伏筆，後面有回應」的結構感。

## 4. 隨機性與可控性設計

- **隨機種子（seed）全程可控且可重現**：同一組參數＋同一 seed，必須能重現完全相同的生成結果（方便除錯與使用者「這次生成我很喜歡，想再聽一次」的需求）
- **分層鎖定機制**：允許使用者鎖定某一層的輸出、只重新生成其他層。例如「鎖定和聲骨架（第二層），只重跑節奏與旋律（第三、五層）」——這對應原專案文件 Phase 5「同一個和聲、不同節奏處理」的教學功能，架構上就是「固定某幾層的 random seed，其餘層重新抽樣」
- **參數與隨機性的關係**：使用者可調參數（借用和弦頻率、切分音強度、裝飾音密度、rubato 程度）本質上是在調整各層機率權重表的分佈形狀，而不是調整「隨機性大小」這個單一數值——這是實作時要特別注意的介面設計原則，避免把「多樣性」簡化成一個滑桿

## 5. 驗證方式

規則對不對，最終要靠耳朵判斷，不能只靠程式跑得動就算過關。建議驗收流程：

1. 針對每個已建模的樂團風格，生成 N 次（建議 N ≥ 10），人耳比對「這聽起來像不像該樂團」
2. 檢查同一風格的多次生成之間，是否有明顯可辨識的差異（避免聽起來像同一首歌的複製貼上）
3. 針對加入意圖建模（第 3 節）前後的版本做 A/B 比較：有無錨點式生成，聽感上「整體敘事感」是否有差異——這個比較本身可以是 Phase 7 的驗收項目之一
4. 張力曲線的效果驗證：檢查高潮小節附近的不和諧度/力度/節奏密度，是否確實高於曲子平均值（可用簡單的統計檢查，不需要主觀聽感）

**建議實作順序：** 先把七層基礎流程做穩（Phase 1–3 已涵蓋），意圖建模屬於錦上添花——即使沒有它，七層流程配合明確的終止式規則與段落模板，已經能做出「結構上說得通」的探戈曲子。意圖建模帶來的提升，是讓生成結果從「風格上正確」進一步逼近「敘事上連貫」，這個差異在較短、較簡單的生成曲目中不明顯，但生成長度拉到 3-4 分鐘、曲式較複雜時會比較有感——所以放在 Phase 7 這種較後期、資源允許時再做的階段是合理的。
