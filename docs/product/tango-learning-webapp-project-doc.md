# 探戈鋼琴／吉他學習網站 — 專案文件（給 Cursor AI 實作用）

版本：v1.0　語言：繁體中文（含技術英文詞彙，因為要 Cursor 讀）

---

## 1. 專案願景

一個雙語（繁中／英文）的探戈音樂教育網站，讓使用者透過**即時生成的 MIDI 音樂**（而非播放受版權保護的原曲），認識探戈黃金時代不同樂團的節奏、和聲與編制風格，並提供視覺化的「Hint」引導，幫助使用者理解、進而在鋼琴或吉他上模仿該風格演奏。

核心設計原則：
1. **不重製版權內容**——網站只列出真實歌曲的「曲名/樂團/年代」作為教育性質的參考清單，實際播放的一律是根據該樂團風格**規則生成**的原創 MIDI 音樂，不是原曲的轉譜或模仿翻奏。
2. **可解釋優先於黑盒生成**——生成引擎建立在明確的音樂理論規則之上（節奏型態、和聲進行模板、配器邏輯），這樣才能同時拿來做「Hint」視覺化教學，而不是一個使用者看不懂原理的黑盒子。
3. **分階段可驗證交付**——每個 Phase 都有明確、可獨立測試的產出，AI 實作完一個 Phase 就先驗證，再進下一個，不要求一次到位。

---

## 2. 目標使用者與非目標

**目標使用者：** 有一定音樂基礎、自學探戈鋼琴/吉他即興與作曲的人（例如：本專案的原始需求者——具備和聲學基礎、熟悉 MuseScore/MIDI 工作流程的自學者）。不是絕對初學者，但也不是要服務職業探戈編曲家。

**這個網站要做的事：**
- 教育與風格認識（聽出「這是 D'Arienzo 還是 Di Sarli」的耳朵訓練）
- 提供可調整參數的原創風格化音樂生成
- 提供視覺化的和聲/節奏 Hint，輔助實際演奏模仿

**這個網站不做的事（Non-goals）：**
- 不是原曲播放器或串流服務
- 不是自動扒譜（transcription）工具
- 第一階段不做完整的多人協作、帳號系統、社群功能（除非之後 Phase 明確排入）
- 不追求生成音樂在「藝術完整度」上超越真人作曲——目標是**教學上足夠有代表性**，不是取代真正的探戈作品

## 3. 內容基礎（Content Foundation）

網站的樂團/風格分類內容，直接沿用先前已經整理好的兩份參考文件，作為資料建模與文案撰寫的來源：
- 《探戈舞會(Milonga)DJ經典曲目與鋼琴即興素材庫》——樂團分類架構、曲目清單、術語對照
- 《探戈舞會(Milonga)DJ經典曲目與樂團故事(白話版)》——樂團人物故事、白話風格描述、四種性格分類（節奏系🥁／柔情系🎻／氣勢系🎹／戲劇系🌊）

實作時應該把這兩份文件的內容**結構化成資料檔**（見第 6 節 Style Profile schema），而不是整篇文字塞進網頁——文字描述會被拆解成資料欄位（節奏型態、速度範圍、和聲傾向、配器慣例、代表曲目清單等），並且中英雙語各存一份。

## 4. 系統架構

### 4.1 技術棧

| 層 | 技術選擇 | 理由 |
|---|---|---|
| 前端 | React（Vite）+ TypeScript | 元件化、生態成熟，Cursor 熟悉度高 |
| 音樂播放 | Tone.js（Web Audio API 封裝） | 瀏覽器內即時播放後端生成的 MIDI/note 資料，支援 soundfont |
| 視覺化 | Canvas 或 SVG 自製 piano-roll／和弦圖元件（不用五線譜引擎，降低複雜度） | 依你的選擇：簡化視覺化優先 |
| 後端 | Python（FastAPI） | 你熟悉 Python/Docker；未來可接 music21、pretty_midi 或自訓練模型 |
| 音樂理論函式庫 | `music21`（和弦/音階驗證）＋ 自製規則引擎（節奏型態、再和聲化邏輯） | 規則要可解釋，優先手寫規則而非直接上生成式黑盒模型 |
| MIDI 產出格式 | 後端回傳結構化 JSON（note events：pitch, start, duration, velocity, track）＋ 可選 `.mid` 檔案下載端點 | JSON 給前端即時播放＋視覺化用；`.mid` 給使用者匯出 |
| 部署 | Docker Compose（前端靜態建置 + 後端 API container），部署到你自己的伺服器 | 沿用你 ElCristal 專案熟悉的模式 |
| 國際化 (i18n) | 前端用 `react-i18next`，所有樂團/風格內容資料檔本身即為雙語 JSON（`zh` / `en` 欄位並存，不是兩套檔案） | 從 Phase 1 就要建好架構，避免後補 |

### 4.2 高層資料流

```
使用者選擇 樂團/性格類型 + 舞曲類型(Tango/Vals/Milonga) + 編制 + 長度
        │
        ▼
前端送出生成請求 → 後端 FastAPI
        │
        ▼
後端規則引擎：
  1. 讀取該樂團的 Style Profile（節奏型態、和聲模板、配器規則、速度範圍）
  2. 依 Style Profile 規則生成和聲進行（chord progression）
  3. 依舞曲類型套用對應左手節奏型態（Marcato/Síncopa/Habanera 節奏骨架）
  4. 依編制決定要生成哪些聲部（鋼琴/吉他/班多鈕琴/弦樂等）
  5. 套用該樂團的裝飾音/配器慣例（力度、觸鍵、留白規則）
  6. 組裝成完整曲式（intro-A-B-A-coda，長度控制在 2-4 分鐘）
        │
        ▼
回傳結構化 JSON（note events + chord 標記 + 節奏型態標記 + key 資訊）
        │
        ▼
前端：Tone.js 播放 ＋ 同步高亮顯示 piano-roll／和弦圖（Hint 功能）
```

## 5. 網站資訊架構（頁面/版面）

1. **首頁 / 介紹頁**：探戈音樂總覽（可沿用你指南第 1 章的內容精簡版）、如何使用這個網站的說明
2. **樂團總覽頁**：兩種瀏覽路徑並存——
   - 依「樂團」瀏覽（D'Arienzo、Troilo、Di Sarli……）
   - 依「性格類型」瀏覽（🥁節奏系／🎻柔情系／🎹氣勢系／🌊戲劇系）
3. **樂團/風格詳細頁**：
   - 樂團故事與白話風格描述（雙語）
   - 代表曲目清單（僅文字列表，附「這首歌是什麼性質」的簡短說明，**不提供原曲播放**，可選擇性附外部連結如 YouTube/Spotify 供使用者自行查詢，但不內嵌播放器以避免版權疑慮）
   - 「生成這個風格的音樂」按鈕 → 進入生成器
4. **生成器頁面（核心互動頁）**：
   - 參數面板：舞曲類型（Tango/Vals/Milonga）、編制（鋼琴獨奏／鋼琴+吉他／+班多鈕琴／完整樂團）、長度（滑桿，2-4分鐘，預設約3分鐘）
   - 播放器（Tone.js）＋ 進度條
   - Hint 視覺化面板（piano-roll + 和弦標記 + 目前 key + 節奏型態標籤）
   - 匯出按鈕（下載 .mid）

## 6. 資料模型：Style Profile Schema

這是整個系統的核心資料結構，每個樂團一筆，欄位設計要能同時餵給「生成引擎」和「網頁文案顯示」。

```json
{
  "id": "di_sarli",
  "name": { "zh": "Di Sarli", "en": "Carlos Di Sarli" },
  "personality_type": "smooth_powerful",  // rhythmic / lyrical / smooth_powerful / dramatic
  "personality_emoji": "🎹",
  "era": { "start": 1939, "end": 1958 },
  "bio": {
    "zh": "……（白話版文件內容）",
    "en": "……"
  },
  "sound_description": {
    "zh": "……",
    "en": "……"
  },
  "tempo_bpm_range": [58, 66],
  "rhythm_patterns": ["marcato_en_dos", "pesante"],
  "harmonic_tendencies": {
    "primary_mode": "harmonic_minor",
    "typical_progressions": ["i-iv-V7b9-i", "descending_fifths"],
    "borrowed_chords_frequency": "medium",
    "dissonance_level": "low",
    "voicing_style": "octave_unison_bass"
  },
  "articulation": {
    "staccato_level": "low",
    "rubato_level": "high",
    "dynamic_contrast": "high",
    "pause_frequency": "high"
  },
  "instrumentation_defaults": ["piano", "bandoneon", "strings"],
  "reference_songs": [
    { "title": "Bahía Blanca", "type": "tango" },
    { "title": "Rosa Morena", "type": "milonga" }
  ]
}
```

> 註：`harmonic_tendencies` 裡的欄位是**風格傾向**（供生成引擎調整機率權重），不是「這個樂團專屬 key」——如同前面討論過的，key 本身不是樂團辨識特徵，這個 schema 刻意不放「signature_key」欄位，避免誤導使用者。

## 7. Phase 規劃

每個 Phase 結束都要有明確、可獨立驗證的產出（demo-able），驗證通過才進下一個 Phase。

### Phase 0：專案骨架與內容資料化
**目標：** 把現有文字內容轉換成結構化資料，架好前後端骨架，但先不做生成邏輯。
- [ ] 建立 monorepo 結構（`/frontend`, `/backend`, `/docker-compose.yml`）
- [ ] 把兩份參考文件裡至少 5-6 個代表性樂團（建議先選：D'Arienzo、Troilo、Di Sarli、Pugliese、Canaro、Biagi，涵蓋四種性格類型）轉成上述 Style Profile JSON，雙語欄位皆填
- [ ] FastAPI 後端骨架：健康檢查 endpoint、靜態讀取 Style Profile 資料的 endpoint
- [ ] React 前端骨架：路由（首頁／樂團列表／樂團詳細頁），i18n 架構就位（中英切換能運作，即使內容還不多）
- [ ] Docker Compose 可以一鍵跑起來
- **驗收標準：** 開瀏覽器能看到樂團列表頁，切換語言正常運作，點進任一樂團能看到雙語故事文字，資料是從後端 API 抓的（不是前端寫死）

### Phase 1：MVP——單一編制的音樂生成與播放
**目標：** 使用者可以選一個樂團風格，生成一段鋼琴獨奏 MIDI 並播放。
- [ ] 後端規則引擎 v1：
  - 依 Style Profile 的 `harmonic_tendencies` 生成一段和聲進行（先用固定曲式模板：intro-A-A'-coda，長度先抓 1-2 分鐘即可，不用一開始就做到 3 分鐘的完整 A-B-A）
  - 依 `rhythm_patterns` 套用對應的左手節奏骨架（先做 Marcato en cuatro / en dos / Síncopa 這幾種最核心的）
  - 只生成鋼琴單一聲部（左手伴奏 + 右手簡單旋律骨架）
  - 回傳結構化 note event JSON
- [ ] 前端：Tone.js 讀取 note events 並播放（用內建鋼琴 soundfont 即可，不用自建音色）
- [ ] 生成器頁面雛形：選樂團 → 按「生成」→ 播放
- **驗收標準：** 選 D'Arienzo 跟選 Di Sarli 生成出來的鋼琴段落，節奏聽感要有明顯差異（能驗證規則引擎真的有依 Style Profile 產生差異，不是每個樂團都長一樣）

### Phase 2：完整曲式與長度控制
**目標：** 生成的音樂長度、結構更接近真實探戈曲子。
- [ ] 曲式模板擴充為完整 intro–A–過渡–B–過渡–A'（再現）–coda（對應你指南第 6 章的典型曲式）
- [ ] 長度參數化：使用者可調整目標長度（2-4分鐘），生成引擎依此決定重複/發展段落數量
- [ ] 加入基本的「漸進式闡述」邏輯：主題第一次出現保持單純，再現時加裝飾音/變化（呼應你指南「從簡到繁」的黃金法則）
- **驗收標準：** 生成一首「約3分鐘」的曲子，聽感上有清楚的段落對比（不是從頭到尾同一個 loop）

### Phase 3：舞曲類型與編制選項（風格微調 Tuning）
**目標：** 加入 Tango / Milonga / Vals 切換，以及編制選項。
- [ ] 舞曲類型參數：
  - Vals：3/4 拍節奏骨架
  - Milonga：3+3+2 或標準米隆加節奏骨架
  - Tango：原本的 2/4 或 4/4
- [ ] 編制選項：
  - 鋼琴獨奏（已有）
  - 鋼琴 + 吉他（吉他聲部：先做簡單的節奏刷奏/分解和弦伴奏邏輯，不用一開始做到指彈編曲）
  - + 班多鈕琴（旋律/對位聲部）
  - 完整 Orchestra（鋼琴+吉他+班多鈕琴+弦樂骨架，簡化配器即可，不用做到真實管弦法）
- [ ] 後端依編制決定要生成哪些聲部的 note events，前端用不同音色播放（Tone.js 多軌）
- **驗收標準：** 同一個樂團風格，切換 Tango/Milonga/Vals 節奏骨架要正確對應；切換編制時聲部數量與音色要正確增減

### Phase 4：Hint 視覺化功能
**目標：** 加入教學導向的視覺化，這是整個網站教育價值的核心。
- [ ] Piano-roll 視覺化元件：隨播放進度即時捲動高亮顯示音符（類似 Synthesia 但簡化）
- [ ] 和弦標記軌：在 piano-roll 上方顯示目前和弦（例如 `Am`, `E7(♭9)`），隨播放同步高亮
- [ ] 節奏型態標籤：顯示目前使用的節奏型態名稱（雙語，例如「Marcato en dos／兩拍標記」），可點擊查看白話說明（沿用術語對照表）
- [ ] Key 資訊顯示：清楚標示「這段生成音樂目前的 key 是什麼」，並附上一句誠實的說明（例如：「這不是 XX 樂團的專屬 key，只是這次生成剛好選到的調性」），避免誤導
- **驗收標準：** 使用者可以一邊聽播放、一邊看著 piano-roll 與和弦標記同步跑，並且能點擊節奏型態標籤看到白話解釋

### Phase 5：進階再和聲化與參數微調
**目標：** 讓使用者能更細緻地「調」生成結果，貼近你原本想要的「風格微調」。
- [ ] 進階參數面板：借用和弦頻率、切分音強度、裝飾音密度、彈性速度(rubato)程度等滑桿
- [ ] 讓使用者可以「鎖定」某個生成結果的和聲骨架，只重新生成節奏/裝飾，或反過來——方便對照學習「同一個和聲、不同節奏處理」與「同一個節奏、不同和聲處理」
- **驗收標準：** 調整參數後重新生成，聽感與 Hint 視覺化要能反映參數變化（例如調高切分音強度，piano-roll 上明顯看到節奏位移增加）

### Phase 6：匯出、儲存與分享（依需求決定是否要做）
- [ ] 匯出 `.mid` 檔案下載
- [ ] （可選）匯出簡易 MusicXML，方便你直接匯入 MuseScore 進一步編輯——**這個對你個人使用價值很高，建議優先**
- [ ] （可選）使用者可儲存生成參數組合成「我的 preset」（需要後端儲存，屆時再評估是否要帳號系統）

### Phase 7（可選，較長期）：資料驅動的生成引擎升級
**目標：** 從規則引擎升級成更貼近真實錄音統計特徵的生成方式，且不牽涉重製受版權保護的旋律本身。
- [ ] 用你已有的 Python/ML 背景，分析（僅供內部訓練用、不對外重製）節奏型態、和聲轉換機率等統計特徵，改良規則引擎的機率權重
- [ ] 評估是否要接入輕量 Markov chain 或其他可解釋的統計模型，取代目前完全手寫的規則
- [ ] 與 ElCristal 專案的分析工具鏈整合可能性（同屬你的探戈音樂技術生態圈，屬於長期加分項而非必要功能）

## 8. 版權注意事項（實作時務必遵守）

- 資料庫裡的「代表曲目清單」只存**曲名、樂團、年代、簡短風格說明**，絕不儲存或提供原曲音檔、樂譜掃描檔、歌詞。
- 若要提供「延伸聆聽」連結，一律連到外部平台（YouTube/Spotify）由使用者自行點擊，不在網站內嵌入原曲播放器或串流。
- 生成引擎的和聲進行模板（如 `i-iv-V7b9-i`）是**音樂理論公有知識**（和弦級數進行本身不受版權保護），可以自由使用；但要避免生成引擎「巧合地」複製出某首知名探戈的完整主題旋律——建議在生成邏輯裡加入基本的旋律隨機化/變異機制，不要用固定的旋律庫。

---

## 9. 給 Cursor 的實作提示

- 每個 Phase 開一個獨立的 git branch 或至少獨立的 commit 序列，方便回頭驗證與 rollback。
- Style Profile 資料檔建議用 `/backend/data/style_profiles/*.json`，一個樂團一個檔案，方便之後擴充樂團數量而不動到程式碼邏輯。
- 節奏型態骨架（Marcato/Síncopa/Habanera/3+3+2 等）建議寫成獨立、可測試的純函式（輸入：小節數+BPM，輸出：note event 時間軸），方便未來新增舞曲類型或樂團時重用。
- i18n 的文案 key 命名建議照頁面/元件分 namespace（例如 `orchestra_detail.bio`、`generator.tempo_label`），避免後期文案散亂。
